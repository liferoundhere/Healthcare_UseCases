# The 3D stage (paused)

`stage/` is a Three.js presentation: slide-deck navigation through 13 hospital worlds, one per story, with presenter tools and an optional narrated edition. It is paused. The 2D showcase is the active deliverable. Do not extend the stage as a side effect of other work.

Two files here are live regardless, because the showcase depends on them:

- `stage/js/narrative.js`: generated story data. Never edit by hand.
- `stage/tools/gen_narrative.mjs`: the generator. See `edit-story`.

## State it was left in

Know this before touching it:

- `js/scenes.js` and `js/hospital.js` are healthcare-specific: 13 hospital worlds that read node ids, link ids, step states and callouts from `narrative.js` and only decide where each node stands and where the camera goes.
- `js/content.js` and `js/script.js` still hold the starter template's sample copy ("Your deck", "Presenter Name", placeholder scenes, talking points and narration). The deck text has not been written for healthcare.
- `stage/README.md` is the starter template's README. It points to `../references/stage-engine.md`, which is not in this repository.
- There is no `media/` folder and no narrated edition checked in.

If asked to resume the stage, say which of these you are addressing first.

## Run

```bash
cd stage && python3 -m http.server 8765
```

Stage: `http://localhost:8765/`. Talking points: `http://localhost:8765/talking-points.html`. Presenter window: P. Talk track: add `?talktrack`. Three.js and the fonts are vendored in `stage/vendor/`, so it runs offline.

## Files

| File | Role |
|---|---|
| `js/content.js` | `DECK`, `PRESENTER`, `SCENES` (copy, beats, notes, layouts), `VERSES` (live links), sources |
| `js/scenes.js` | One export per scene id: node placement and camera per step |
| `js/hospital.js` | Hospital world kit: layouts, devices, links, the Cloud Control plane that appears in the Cisco phase |
| `js/particles.js` | `FORMATIONS`: every scene id must be mapped |
| `js/script.js` | `POINTS` (talking points) and `NARRATION`, one entry per click per scene |
| `js/kit.js`, `js/core.js` | Building blocks |
| `js/film.js`, `js/avatar.js` | Narrated edition playback |

`NARRATION[scene].length` must equal that scene's `notes.length`. `export_narration.mjs` exits with the mismatched scene ids if it does not.

## Review

```bash
cd stage && npm i -D puppeteer-core
```

```bash
cd stage && CHROME=/opt/pw-browsers/chromium node tools/review.mjs http://localhost:8765/ 1440 900
```

Screenshots every scene into `stage/tmp/review` and reports console errors. Needs the server running. `CHROME` sets the browser path; the default is `/usr/local/bin/google-chrome`. Headless WebGL is slow, so the tool waits for scenes to settle.

## Narrated edition

```bash
pip install edge-tts rangehttpserver
```

```bash
cd stage && node tools/export_narration.mjs tmp/narr.json
```

```bash
cd stage && bash tools/sync_narrated.sh ../narrated
```

```bash
cd stage && python3 tools/gen_audio.py tmp/narr.json ../narrated/audio
```

```bash
cd narrated && python3 -m RangeHTTPServer 8766
```

- `sync_narrated.sh` copies the code into a sibling `narrated/` folder and flags it as the narrated edition. Re-run it after code or copy edits.
- `gen_audio.py` renders one clip per click with edge-tts, which calls an online speech service. It needs network access and sends the narration text out. Re-run it after narration edits.
- `narrated/`, `stage/tmp/` and audio are outputs. Ask before committing them; none are tracked today.

## Docs

```bash
cd stage && node tools/gen_docs.mjs ../narrated/audio/manifest.json
```

Writes `TALKING_POINTS.md` and `SCRIPT.md` from `content.js` and `script.js`. The manifest argument is optional and adds clip timings.

## Rules that bite here

- The copy rule in `content.js` is the same as everywhere: no em dashes.
- All the content rules in `CLAUDE.md` apply to deck copy, talking points and narration. Spoken narration has no room for a citation tag, so a Modeled outcome must be said as modeled, and a figure must name its source in the sentence.
- The 3D worlds must agree with the 2D stories. If they differ, `narrative.js` is right and the placement in `scenes.js` is what you change.
